## 先说清楚我读了什么、没读什么

八期周报全部读完：李卓凡 9/28—10/25 四期，胡博同样四期。读的时候只看「本周思考」，实验过程只扫了标题，用来理解上下文。

**没读的**：李卓凡的 29 份 Agent 实验主记录、胡博的实验附件和 Obsidian 笔记原文。所以下面引用的数字都来自周报里他们自己写下的结论，我**没有回查实验记录、没有复现**。这一点先说清楚，免得后面看着像核对过。

## 一、两条不一样的成长曲线

### 李卓凡：从「看懂机制」到「怀疑口径」

第一周他还在讲「结合代码看 ReAct 循环，比只看书里概念更容易理解」，是在确认自己真的看懂了机制。第二周转去关注 Agent 之间怎么传信息（Mostik、A2A），也第一次提到 PRD——先写需求再 Vibe Coding。

真正的转折在第三周。那期他写了六个「关于」：uv 环境、知识库人工检查、学习节奏、记忆选型、检索方法、混合检索。几乎每一条的落点都是「**这个数字该怎么读**」——HNSW 把 ef 从 20 提到 200，召回 55.7%→99.2%，但耗时涨到 4.75 倍；稠密和 BM25 融合后依然覆盖全部相关文档，可 MRR 从 1 掉到 0.9。到第四周就变成了那句最直白的话：**「检索到证据只是第一步，还要检查回答是否准确使用了证据」**。

### 胡博：从「机制理解」到「给自己造工具」

第一周他的三句话很干净：Agent = LLM + 上下文 + 工具；消融实验说明各组件各管一段；**「返回了答案，不等于完成了任务」**。第二周把上下文工程落到「管理 Agent 每次决策时能看到的信息」，并开始在 Obsidian 里建双向链接。

第三周是他跨度最大的一期：自己搭 Wiki.js + Dify + Ollama 的 bge-m3，同时跑了四个实验，还写了团队知识库的四类分区。第四周干脆做了个 `archive_learning_note` 的 MCP 工具，把「建目录、命名、保存」这套重复动作接过去，还处理了幂等（重复调用返回 `unchanged`）和冲突（同名不同内容返回 `conflict`）。

两条曲线方向不同：一个往「怎么判断结果可信」走，一个往「怎么把能力变成工具」走。但第四周我读到一个交汇点——两人都在说同一件事：**产出看起来完整，不等于它是对的**。

## 二、几处让我改主意的具体结论

**① 缓存率高不等于方案好。** 李卓凡第二周做过六种上下文方式的对照：稳定前缀缓存命中 97.09%，改一下系统时间就掉到 3.90%；滑动窗口反而保住了较高缓存，却丢了关键编号。也就是说缓存效率和信息完整性是**两个独立指标**，我以前默认把它们当成一个东西。

**② 增加检索信号不保证结果变好。** 同一语料下两路融合，Recall 仍是 1，但首个相关结果从第 1 掉到第 2，MRR 1→0.9；再加神经重排，顺序变了，MRR 还是 0.9。我原先的直觉是「融合一定更强」，这条数据直接把它推翻了。

**③ 收益要连代价一起报。** 胡博第三周的 Agentic RAG 对照很清楚：简单问题上两种方法证据召回都是 100%、检索都是 1 次，多做推理没有收益；复杂问题上单次检索只有 8.3%，Agentic 提到 91.7%——但检索次数 1→3.5，延迟 8.1 秒→65.7 秒。结论只能是**有条件成立**，不能写成「Agentic RAG 更好」。

**④ 「能力接入了」和「能被找对」是两件事。** 胡博第四周主动工具发现的三种策略分别选对 4/8、4/8、5/8，工具说明的 token 少了 91.74%，但耗时反而更长（33.050 秒对 28.090 秒）。省上下文和提速度不是同一件事。

**⑤ 事实变了，旧信息不一定没价值。** 李卓凡第三周比较 Mem0 Platform 的 v2 / v3 时写下的这句，是我读这八期里最意外的一条：写入时整合便于维护当前状态，保留历史便于追溯变化。构建记忆系统前要先想清楚「要当前状态还是要变化轨迹」。

## 三、新发现

**两个人做知识库的路线完全不同，但目标一样。**

李卓凡走的是 llm_wiki：按脑机接口、深度学习、Agent 分类上传资料，用关系图串联，靠 Codex 建关联。胡博走的是工程化的 RAG：Wiki.js + PostgreSQL + Dify + 本地 bge-m3，1024 字符分段、50 字符重叠。一个偏「整理」，一个偏「检索」。这两条路可以直接拿来对照，而我两边都没做过。

**一个共同的、还没补上的缺口：人工核对。**

李卓凡第三周自己写了「现有关系尚未经过人工后期修正」；胡博的 RAG 链路里，我没看到他把检索质量作为一个评估对象。胡博第四周的执行工具实验倒是给了个更狠的例子：代码执行降级成本地进程，网络请求还能成功，但没达到隔离要求——**跑通了，恰恰是没达标**。

这和我上一期周报里写的是同一类错误：9-1 的 `privacy_boundary` 召回 0.00，12 项验收 1 项红，第一反应是想办法修绿，而根因是评测器自己漏抓。自动化产出的可信度，必须独立验证一次，否则「全绿」只是没人检查。

**还有一点是关于学习方式本身的。** 胡博第四周那句「从被动接受别人传输的知识，转变到在现有个人学习土壤上长出自己对知识的理解」，解释了他为什么愿意花一周去写一个只有自己在用的归档工具。这句话比任何方法论都直接。

## 四、我可以直接搬过来的学习路径

**路径一：把「评价口径」当成独立的学习单元。**

他们两个人每一期都同时交付「数据 + 口径说明」。李卓凡第三周甚至把两种口径并排报：全用例流程通过率 6.67%，仅已评分 6 题的通过率 66.67%，技术失败单列、不补裁判 0 分。胡博第三周的用户记忆表则是 60 用例 × 3 层 × 4 策略共 240 次评估、1042 次调用，最后给四行通过率。

我打算从下周起每次实验先写三行再动手：**指标口径是什么、证据等级是什么、代价是什么**。

**路径二：复现「融合反而降 MRR」这个最小实验。**

李卓凡第三周用的是官方 12 篇文档、5 条查询，指标 Recall/Precision/MRR@5。这套规模小到我在本机一晚上能跑完，而且结论反直觉——正好适合放进共同知识当可复现的例子。跑完再对照胡博第三周那张 Annoy / HNSW 的表（300 条文档，Recall@10 都是 1.0，差别在构建 13.20 ms 对 77.68 ms、增量 8.27 ms 对 33.83 ms、文件 1.40 MB 对 1.02 MB），就能把「召回一样、代价不同」这句话落到数字上。

**路径三：把记忆策略表搬到 EEG 场景。**

胡博那张四策略表（enhanced_notes 86.7%、json_cards 85.0%、advanced_json_cards 81.7%、notes 80.0%）的结论是「增加结构复杂度不会自动带来更好的记忆效果」。我的 EEG 项目里，跨被试、跨 session 本质就是跨会话记忆——被试间差异可以当作「事实变化」来处理，正好用得上李卓凡那条 v2/v3 的区分。

**路径四：找一件自己的重复劳动做成工具。**

胡博的归档 MCP 是可抄的模板。我每周要重复的是：把实验输出整理成周报素材、按周归档。这件事我上周还在手工做。

## 五、新想法

**① 三人应该先对齐一份「评价口径约定」。**

现在三个人的口径明显不同：李卓凡分层报（6.67% / 66.67%），胡博直接给通过率（86.7%），我报的是「12 项里 11 过 1 失败」。谁都没错，但把三个人的数字并排放在一起，读者会误以为可以直接比大小。我建议在共同知识里放一份约定：指标怎么定义、失败怎么计入、什么算完成。这件事我可以先写草稿。

**② 「自动生成的东西必须被独立验证」可以做成一条共同的工作原则。**

它同时出现在三个地方：我的评测器漏抓、李卓凡的 AI 建关联未人工修正、胡博的执行工具「跑通但没隔离」。这不是三个 bug，是同一种失败模式。

**③ 跨被试的「记忆」可能比「模型」更值得投入。**

李卓凡第三周提到想借 Mostik 的 Agent 交流方式探索 BCI 跨被试问题，并和李昱辉讨论过从跨被试、跨范式两个方向入手。胡博的记忆分层评估又提供了现成的方法。两件事接起来，是我目前看到最有想象力的方向：**把被试间的分布差异当成记忆里的「事实更新」来建模**，而不是每次都重新训一个模型。

## 六、对我自己的影响

坦白讲，读完八期我最直接的感受是差距不在勤奋，在**产出的结构**。

他们每周都是「实验数据 + 一句可检验的结论 + 一个反面例子」，我过去四周的报告里「跑通」的比重偏高，「对照」的比重虽然在上升但还是少。同一周里他们既有数字也有对数字的怀疑，我常常只有数字。

下周（11/2—11/8）我做两件事：路径一（每次实验先写口径三行）和路径二（复现融合降 MRR），产出两份能放进共同知识的东西。

## 疑点与适用范围

- 我只读了周报正文，没有读实验记录、附件和 Obsidian 原文。文中所有数字均为**转述**，未经我复核。
- 李卓凡的检索指标（12 篇文档 / 5 条查询）和胡博的（300 条文档）语料规模不同，**不能横向比大小**，只能比趋势和代价。
- 胡博第三周的用户记忆表是他自己环境下的结果（DeepSeek + 1042 次调用），我的场景未必可比。
- 我把「两个人的共同点」归纳成五条，这是我的读法，不是他们的共识；文中已在各处标明出处，便于核对。
