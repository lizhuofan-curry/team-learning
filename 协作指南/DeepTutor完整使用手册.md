# DeepTutor完整使用手册

面向第一次使用 DeepTutor 的团队成员。先跟着第3—8节完成“一份课件 → 一次有引用的问答 → 一道独立练习 → 一份学习记录”，其他功能按实际需要再用。

## 1. 本手册对应什么版本

核对日期：2026-10-28。本手册以本机已安装的官方项目为基础，版本为 `a31d82624c27d75f4e771d4fcb78dce16470b383`，远端为 [HKUDS/DeepTutor](https://github.com/HKUDS/DeepTutor)。本机界面端口为3782，与这一版官方项目的启动方式一致。

团队现有[第一章真实课件验收](../课程资料/计算机网络/使用记录/第01章概述_DeepTutor验收_2026-10-27.md)也使用此提交。已有一次本人[单位换算提问与反馈](../课程资料/计算机网络/使用记录/本人首次使用_单位换算_2026-10-27.md)，不意味着全组都完成使用或掌握课程。

核实范围：本机源码、CLI定义、中文界面翻译、启动脚本、上述真实课程记录，并参考[官方文档](https://docs.deeptutor.info/)。本次编写没有重装环境、改变模型配置或重新执行所有功能。文中的进阶功能属于当前源码可见的使用路径，尚未逐项做团队真人验收；官方新版本的界面可能变化。

## 2. 先分清几个容易混淆的东西

| 名称 | 用来做什么 | 是否等同于其他东西 |
|---|---|---|
| DeepTutor聊天 | 向模型提问，按已选资源调用检索等工具 | 能聊天不代表课程库已建好 |
| 知识库 / Knowledge Base / KB | 把一组课程文档解析、建立可检索索引 | 文件上传成功不代表索引就绪 |
| 沉浸式阅读 | 把一份文档或媒体放在阅读器旁逐页讨论 | 阅读材料不等于向量知识库 |
| DeepTutor课程 | 组织某门学科的资源、学习对话与进展 | 建立课程卡片不等于已导入课件 |
| 内容工作区 | 区分项目的文件与学习数据范围 | 不是Obsidian个人库，也不是模型的上下文窗口 |
| 学习空间 | 管理可复用笔记本、题库、技能等资源 | 不是团队Git仓库 |
| Obsidian个人知识库 | 保存你自己的理解、试错、来源和复习笔记 | 不会因为使用DeepTutor就自动更新 |
| GitHub团队知识库 | 共享有来源的课件、实验、已整理记录并互审 | Git拉取不会自动更新本机DeepTutor索引 |

建议：DeepTutor帮助你学习；Obsidian保存自己的理解；团队仓库交换可核对的材料和经验。三者联动见[团队知识库完整使用手册](团队知识库完整使用手册.md)。

## 3. 打开系统，确认可以开始学习

### 3.1 已经安装好的本机

李卓凡的Mac已存在桌面启动项“DeepTutor 课程学习.command”。双击后会调用项目的“启动课程学习.command”，等待后台与网页就绪，再打开 `http://localhost:3782/chat`。它是这台电脑已有的便捷入口，队友电脑需要使用各自安装位置，不能照抄他人的绝对路径。

如果网页已开着，先直接访问主页，避免重复启动。关闭浏览器标签页不一定会停止后台服务；本机项目另有“停止课程学习.command”。不要为解决端口问题随意结束其他软件的进程。

通用终端方式：在自己的DeepTutor环境可用、运行目录已确定的前提下执行：

```bash
deeptutor start --detach --no-browser
```

以终端实际打印的地址为准；本机常用前端3782、后端8001，不要求队友修改为相同端口。

### 3.2 队友还没有安装

已安装就跳过本节，不重复覆盖配置。需要安装时，可把下面的话交给Agent：

```text
请阅读HKUDS/DeepTutor官方AGENTS.md、SKILL.md和docs-for-user/AGENT_SETUP.md，
先检查我的现有安装、Python、Node和目标磁盘目录，再帮我安装完整Web版。
Windows使用我选择的盘符与目录，保留已有资料和配置，不把API Key写进聊天或Git。
我需要课程知识库，请分别验证聊天模型、embedding和一份真实课程资料的检索。
最后返回启动方式、实际访问地址、数据目录、已经验证和未验证的功能。
```

当前源码安装指导要求Python3.11—3.14及Node.js22 LTS。Windows使用自己可用的 `py -3.X`，Python虚拟环境程序通常在 `.venv\Scripts\`；Mac/Linux通常在 `.venv/bin/`。这与周报工作流脚本支持Python3.9+是两回事。

从源码安装的核心过程是克隆官方仓库、创建虚拟环境、安装项目、在 `web/` 安装前端依赖、初始化和配置，再启动。官方也有包含网页资源的PyPI安装路径，不需要初学者同时尝试四种安装方式。完整步骤以[官方安装入口](https://docs.deeptutor.info/get-started/)和当前源码中的 `docs-for-user/AGENT_SETUP.md` 为准。

### 3.3 检查模型：聊天和检索是两项配置

在左下角“设置”中检查模型配置：

1. 聊天模型负责理解问题与生成回答。
2. Embedding模型负责把文档和问题转换为向量，是LlamaIndex等检索库的重要依赖。
3. 文档解析负责从PDF、PPTX等提取可读内容，和上述两个模型也不相同。
4. 网络搜索、图片、视频或语音服务是可选配置，不是普通文字课程问答的全部必需项。

已有课程验收采用既有DeepSeek聊天配置和SiliconFlow的 `BAAI/bge-m3` embedding，1024维；这是历史运行条件，不能假定队友已有这些账号或必须选择同样供应商。不要把团队成员的Key复制到自己的仓库。

如需让Agent排查，可运行当前安装支持的：

```bash
deeptutor doctor --format json
deeptutor doctor --online --format json
```

即使在线聊天检查成功，也仍需单独导入、检索一份课程资料，才能证明RAG可用。诊断输出给别人前遮盖账号、密钥和私有地址。

## 4. 熟悉主页：先会用这几个位置

按当前中文界面和代码，主要入口如下。侧栏可调整顺序或折叠到“更多”，因此找不到某项时也检查“更多”或学习空间。

| 位置 | 你可以做什么 |
|---|---|
| 左侧“主页” | 新建普通学习对话 |
| 左侧“近期” | 回到之前的学习对话继续追问 |
| 输入框左下“聊天” | 切换当前能力，例如聊天、主动提问、出题、可视化；更多能力按当前菜单显示 |
| 输入框旁“资源” | 选择知识库、上传附件，引用历史对话、书籍、阅读、笔记本、题库等 |
| 已选知识库标签 | 确认这一轮实际附带哪个课程库；需要时移除 |
| 顶部活动/详情按钮 | 展开工具、检索、引用、文件等执行情况 |
| 顶部导出按钮 | 保存对话Markdown，便于整理学习证据 |
| 左下“设置” | 模型、解析、工具、工作区等配置 |

你之前截图里的“资源 → 知识库 → 1项已选”，就是已经为当前对话选了一项知识资源。下面输入框里还能看到 `sophomore-computer-networks` 标签。知识库是从这里挂载使用，课件不是每次提问都重新上传。

输入区显示的百分比是当前对话的上下文预算占用，不是课程掌握度或账户余额。回答下方的token与缓存统计反映该轮模型用量，不能直接换算为实际费用或剩余免费额度；费用以本人供应商账单为准。上下文很长时可按章节新建对话，保留学习目标、必要引用和未解决问题，避免整段复制旧聊天。

麦克风通常用于把当次输入转成文字，不能因为有麦克风就认定已配置好语音服务；发出前先看转写文字是否正确。

## 5. 建立一门课的知识库：第一次从一章开始

### 5.1 选什么资料

首选自己正在上的课的一章课件、可提取文字的PDF教材章节、自己核对过的笔记或一道带题干的练习。不要一开始把整个下载目录、其他课的文件和测试答案一起导入。

下面的计算机网络材料仅为历史测试实例，不代表本次必学课程或正式分工；请优先选择自己的实际资料。团队已有[计算机网络课程入口](../课程资料/计算机网络/README.md)及[第一章PPTX](../课程资料/计算机网络/课件/计算机网络_课件_第01章概述_第8版.pptx)。先从GitHub拉取或下载原文件，确认你能直接打开，再导入自己本机的DeepTutor。

来源、教材版本、原文件名和章节记录在课程README或[来源与章节目录](../课程资料/计算机网络/来源与章节目录.md)。发现不同教学版本时标明差异，不能混为老师正在讲的同一份材料。

### 5.2 格式与大小

当前代码的通用文件安全上限为每份 `200 × 1024 × 1024` 字节。具体可选格式取决于所选解析器和知识引擎，以上传对话框实际列出的政策为准。

| 资料 | 建议 |
|---|---|
| PDF、DOCX、PPTX、XLSX、EPUB | 当前文档路由有对应处理；优先用内容清晰、可选中文字的资料 |
| TXT、Markdown、部分代码与结构化文本 | 当前路由支持直接读取；并非所有后缀在每种引擎都能用 |
| 旧版DOC/PPT/XLS | 不把通用白名单视为所选解析器已成功支持；优先另存为DOCX/PPTX/XLSX或PDF后试验 |
| 扫描PDF、图表、公式图片 | 需要合适OCR或视觉解析配置；“文字提取成功”不代表模型看懂图片 |
| 视频、音频、网页 | 优先看第10节的沉浸阅读；不要把知识库上传框当万能视频解析器 |
| 压缩包、虚拟环境、模型权重 | 不作为第一门课知识库资料；先选实际需要的文档 |

“文件格式允许上传”“内容能正确解析”“检索能命中”“回答正确”要分别验证。

### 5.3 页面建立步骤

1. 打开“学习空间 → 知识中心/知识库”，当前源码路由为 `/knowledge-bases`。
2. 查看是否已有同一门课的库。有就打开并看文件列表，避免再建同名重复库。
3. 没有时选择“创建知识库/新建知识库”。不同语言可能显示 `New knowledge base`。
4. 选择“创建新库”，不是“链接已有索引”。后者要求你已有符合引擎格式的索引目录，不能指向一个普通PPT文件夹冒充索引。
5. 填写与本次资料对应的可识别名字，例如 `my-course-kb`；不要沿用别人的测试库名。这个名字是当前成员本机的库名，不是GitHub仓库名。
6. 新手先选已有运行记录的LlamaIndex；不用为了功能多就马上改GraphRAG、LightRAG或PageIndex。
7. 确认Embedding模型可用；选择需要的存储工作区，首次可使用账户资源库/默认范围，不随意迁移历史数据。
8. 添加一份实际课件，提交创建；等待解析与索引任务结束。
9. 打开库的文件列表，确认原文件、文档数量、状态和错误提示，再做第6节的检索验证。

官方概述见[知识中心](https://docs.deeptutor.info/explore/knowledge/)。本手册上述按钮和状态也对照当前 `web/components/knowledge/CreateKbModal.tsx`、`KbStatusBadge.tsx` 及API文件策略核对。

### 5.4 等待与错误：怎样算“入库完成”

| 看到的情况 | 含义与操作 |
|---|---|
| 上传完成 | 只说明文件已传输，继续等解析、embedding和索引发布 |
| 处理中 / Processing live | 查看任务进度和错误，不连续重复提交同一个文件 |
| 就绪 / Ready | 当前索引可用的一个条件；再检索实际内容验证 |
| 需要重新索引 / Needs reindex | 配置或索引签名不匹配，核对改了什么后再重建 |
| Embedding模型被删/需检查 | 先恢复可用模型配置；不要只刷新页面 |
| 错误 / Error | 保留错误、阶段和失败文档；修复原因后重试 |

当前LlamaIndex只有经过验证并发布的新索引才算就绪。单个“解析100%”不是整库可用的充分证据。

### 5.5 后续章节如何加

打开已有课程库，在“添加文档”中上传下一章，等处理结束，再用该章特有关键词提问验证。不要因为第一章能问答就写“全部课程知识库已完成”。

上传的是副本；GitHub课件更新后，本机已上传的旧副本不会自动改变。保留来源版本，按需要更新或重新同步。

## 6. 挂载知识库，完成第一次有依据的问答

1. 回到主页，建立新的学习对话。
2. 点输入框“资源”，进入“知识库”。
3. 勾选自己刚建立的课程库，检查输入框上的库名标签。开始只选一门课，不混选连通性测试库。
4. 关闭资源菜单，输入明确的问题。先问一小段，不直接让它“教会我整本书”。
5. 观察活动记录，确认有检索或相关源文件读取。当前库为LlamaIndex时通常会显示RAG检索；其他知识引擎的工具名称可能不同。
6. 展开回答中的引用，回看课件原页。模型说“来自第78页”还需要实际核对。

通用提问模板（先填入本次资料与问题）：

```text
请先检索当前挂载的【本次资料库】，仅依据检索结果回答【我的实际问题】。
请标明支持结论的来源位置；没有依据时明确说明，不引用无关测试资料。
```

再选一个本次资料没有提供依据、但你实际想确认的问题，检查它能否承认资料不足：

```text
本次挂载资料能否支持【我实际要确认的、资料外的问题】？
请区分资料中的依据与外部推测，没有依据就说明无法确定。
```

核对回答是否诚实承认资料不足；未检索到依据时，不把模型猜测当成已证实结论。不限定学校、学科、年份或固定题目。

## 7. 会追问，也会核对：历史测试实例（计算机网络）

### 7.1 从自己的困惑出发

用户已实际问过：

> 我不理解第2题的单位换算。请结合课件，把1B、1Mbit/s、1000km分别怎样换算讲清楚，每一步都写出单位，并标注课件页码。

“第2题”只在原对话有上下文时才明确；新对话应补全题干：1B数据、1000km光纤、1Mbit/s发送速率，忽略处理与排队时延，光纤传播速率取课件给出的值。

可以继续问：

```text
我仍不明白为什么1B要换成8bit。只解释这一步，写出单位消去的过程。
然后给我一道只换数据长度的类似题，先不公布答案，等我作答再核对。
```

### 7.2 这份真实课件应核对到什么

以下是已留证据的参考核对，不是替你完成独立练习：

| 核对点 | 当前149页PPTX中的位置与结果 |
|---|---|
| 字节与比特 | 74页：1B=8bit |
| 发送时延 | 78页：长度bit ÷ 速率bit/s |
| 光纤传播 | 79页：距离 ÷ 传播速率；200000km/s=200000000m/s |
| 总时延公式 | 82页；83页是发生位置示意图 |
| 题设与算式 | 85—86页：1Mbit/s=1000000bit/s，发送0.008ms、传播5ms、总5.008ms |

原始模型回答曾把总时延公式写成83页，也把前缀约定讲得不够准确。正确区分是M为10的6次方、Mi为2的20次方；不能泛化为“所有数据量用二进制、所有速率用十进制”。课件74页及部分例题的用法应当注明与规范符号的差异，而非将其泛化成新规则。详细核对与规范来源见[本人首次使用记录](../课程资料/计算机网络/使用记录/本人首次使用_单位换算_2026-10-27.md)。

### 7.3 核对引用的五个动作

1. 检查文件名和章节是否真的来自所选库。
2. 分清PPT幻灯片序号、导出PDF物理页、书上的印刷页码。
3. 打开原页，确认该页实际支持这句话；相邻一页也算引用误差，要记录。
4. 对计算自己复算，特别检查B/b、km/m、s/ms/μs和指数。
5. 保留原回答，再另写纠错记录，不把修改稿伪装成系统第一次就完全正确。

纯文字解析可能丢失公式上下标、矢量图与动画。现有第一章验收的索引图片数为0，不能据此声称已完成图示理解。需要看图时回到原PPT，或选择合适PDF/OCR/视觉方案另行验证。

## 8. 怎样从“听懂解释”变成“自己会做”

建议每次学习保留四个阶段：

1. **先表达困惑**：我卡在哪个概念或一步计算。
2. **让DeepTutor解释**：限定课件、引用和解释粒度。
3. **独立回答或计算**：关闭参考答案，自己写出过程。
4. **再核对与总结**：哪里出错、为什么、下一次如何检查。

若本次任务是练习，可使用通用提示词；不需要做题的阅读或项目任务可改为复述、复现或实际应用核对：

```text
基于【本次学习资料与目标】给出一项适合的独立练习。
先只给题目和必要条件，不给答案；我提交过程后，逐步检查相关概念和逻辑，
再出一道针对我错误点的题。不要把“我看过你的解释”记作已掌握。
```

没有独立作答时，记录“已提问并缓解困惑，独立变式题待完成”；答对一次也只说明该题完成，不代表整门课已掌握。老师重视的思考与团队讨论，需要实际表达和交流来证明。

## 9. 把一次学习保存下来，再与团队共享

### 9.1 个人保存

在DeepTutor顶部找导出Markdown按钮，或者复制完整的题干、回答、来源与日期。可以使用笔记本收藏关键回复；收藏不等于Obsidian已收到文件。

自己的Obsidian笔记至少写：日期、章节与资料版本、原问题、检索/回答证据、我实际反馈、核对错误、独立练习情况、后续计划。AI补充解释单列，自己的心得只写自己确实表达或经历过的内容。

### 9.2 团队保存

采用[DeepTutor使用记录模板](模板/DeepTutor使用记录模板.md)，放到 `课程资料/课程名/使用记录/`。原课件放 `课件/`，来源与版本放课程入口；经核对可复用的概念笔记放 `共同知识/主题名/`。

提交一条小范围PR，让队友在自己的电脑导入同一份课件、提问一个问题，并核对至少一个引用或算式。队友应留下自己实际检查的内容，不填写预设的“审阅通过”。具体Git流程见[团队知识库完整使用手册](团队知识库完整使用手册.md)。

### 9.3 三种共享方式不要混淆

| 共享方式 | 队友得到什么 | 队友仍要做什么 |
|---|---|---|
| Git共享原资料与记录 | 课件、来源、使用方法、学习笔记 | 本机建立/更新知识库，配置自己的模型并验证 |
| 每人本地DeepTutor | 各自独立的对话、索引和使用数据 | 通过Git交换可共享成果，不交换密钥与整个运行data目录 |
| 共用部署的多用户DeepTutor | 由管理员配置的共享资源与账号权限 | 按真实账号授权访问；私有学习记录不因同一服务器就默认互相可见 |

当前团队使用Git共享，不自动等于已部署多用户服务器。当前源码还支持关联文件夹/GitHub/Web来源、按需同步，但这是另一个需要配置并验收的功能；本机私有GitHub仓库访问也要单独授权。没有设置、运行同步任务并验证前，不声称Git更新已进入索引。

## 10. 其他主要功能怎么用

以下结合当前源码入口及官方功能说明编写，属于进阶使用路线；除已有第一章课程问答外，本轮没有逐项进行真人验收。界面隐藏时先检查侧栏“更多”和权限/模型配置。

### 10.1 个性化学习：精通之路

入口为“个性化学习 → 精通之路”，路由 `/learning/mastery`。用途是把一个学习目标拆成可练习的知识点。

1. 新建主题，写具体目标，例如“能区分发送、传播时延，并独立完成带单位的计算”。
2. 选相关书籍、笔记本或知识库文件作为材料，不只填课程名字。
3. 检查生成的大纲，删掉这阶段不需要的内容、补上漏掉的知识点。
4. 进入一个知识点进行学习和练习，根据自己的作答接受反馈。
5. 复习已学内容，区分系统评价与本人手动声明，不把进度条等同于实际长期掌握。

当前源码将概念、过程等知识类型分开处理；官方操作概览见[精通之路](https://docs.deeptutor.info/explore/mastery-path/)。建议先完成第8节的小练习，再尝试整条路线。

### 10.2 个性化学习：沉浸式阅读

入口为“个性化学习 → 沉浸式阅读”，路由 `/learning/reading`。适合围绕当前一份材料逐页读，不必先建立向量库。

1. 新建阅读合集，添加一份文本可提取的PDF、PPTX或其他受支持材料。
2. 打开材料标签页，定位正在读的页或节。
3. 选中一段文字，再问“这里为什么成立”；或明确要求读指定页解释。
4. 核对回答的定位，保存自己的高亮与批注。
5. 需要时导出Markdown批注；保留原始PDF的材料可使用其注释PDF导出功能，不能假定所有格式都能保持原版式导出。

文档与媒体有不同的定位方式。视频学习主要依赖字幕/转写和时间戳，不等于模型看过所有画面。没有转写时可以播放但不能可靠解释未读到的语音内容；扫描型文档需要先OCR等处理。详细说明见[沉浸阅读](https://docs.deeptutor.info/explore/reading/)。

### 10.3 课程、书籍、练习与题库

| 功能 | 适合怎么用 | 从哪里开始 |
|---|---|---|
| 课程 | 将同一学科的材料、对话与学习活动放在一起 | 当前源码有 `/courses`，新建课程后在资源区附上已有材料，再开始课程学习/课程聊天 |
| 书籍 | 从已有知识库或笔记组织可阅读的学习内容 | 个性化学习的书籍入口；生成后抽查来源，不把生成书当原教材 |
| 出题能力 | 让模型基于指定章节产生练习 | 主页能力选择中的出题/Quiz，指定范围与题型；先自己答后看解析 |
| 练习 | 做题、维护错题和安排复习 | `/learning/practice`，有题目后选择练习 |
| 题库 | 集中管理题目、标签、答案与来源 | 学习空间 → 题库，路由 `/space/questions` |
| 笔记本 | 收藏有价值的回答和自己的笔记 | 学习空间的笔记本，之后可作为对话参考材料 |

练习与题库在本机当前版本共用题目与复习记录。导入自己的题目支持XLSX、CSV、TSV、JSON，当前文档规定单次最多500题、5MB、64列；使用界面模板，预览校验正确后再确认导入。简答等题可能需要自评，不能把所有评分当成客观正确性保证。已有本机 `docs-for-user/PRACTICE.md` 说明了实际规则。

### 10.4 课程怎样真正用起来

本机当前源码的“我的课程”入口是 `/courses`。它将现有资源建立引用，而不是把所有材料复制成另一份。

1. 打开“我的课程”，点击“新建课程”，填写实际课程名和简要目标。
2. 在课程的资源区域附加第5节已建好的知识库；也可以引用书籍、笔记本、精通之路或阅读合集。
3. 检查资源是否可用；资源不存在或无权限时应先恢复正确来源，不能只看课程卡片还在。
4. 用“新建课程聊天”开始围绕该课程讨论，或用“开始课程学习”进入课程学习流程。
5. 让系统根据材料提出下一步学习建议，自己决定先学哪一节，再记录实际学习和练习结果。
6. 后续回到课程页面找此前对话，避免把所有科目的记录混在默认对话中。

课程页面取消附加某个资源，并不等于删除原知识库；课程与工作区也不是同一个概念。有关资源和按钮以当前 `web/components/courses/CourseResources.tsx` 与课程页面代码为依据，本轮未对这套课程功能进行真人完整试用。

### 10.5 书籍怎样开始生成和阅读

书籍更适合把一段课程资料组织成连续阅读内容，不建议第一天就生成整本教材。

1. 在“个性化学习 → 书籍”打开新建书籍。若没有新建按钮，先查账号权限和功能配置。
2. 填一个小主题，例如“第一章的时延与吞吐量”，选择相应知识库或整理好的笔记作为来源。
3. 查看生成的章节大纲，删掉偏离本章的内容；核对预估生成范围与费用提示。
4. 首轮选择只生成第一章等小范围方式，观察输出再决定继续，而非直接生成大量章节。
5. 阅读生成页面，完成其中的练习或对话，抽查关键结论是否有原始来源支持。
6. 导出Markdown或保留自己的笔记；生成书本身属于AI辅助资料，不能替换原教材、本人心得和真实实验记录。

书籍编写可能持续数分钟，生成任务未结束时不写“整本已完成”。权限、素材和功能说明见[官方书籍指南](https://docs.deeptutor.info/explore/book/)。这部分为源码与官方功能路径说明，不是当前团队已经完成的学习成果。

### 10.6 学习空间、记忆、技能与外部工具

学习空间集中管理可复用资源。DeepTutor的Skills、MCP和模型设置与Codex仓库中的Skills是不同安装位置：团队仓库有 `lab-knowledge-loop`，不等于DeepTutor已加载该Skill。要在DeepTutor使用，先按它自己的技能管理与文件访问方式配置，不能只靠名字假定已安装。

记忆有自己的管理入口，可查看系统保存的学习偏好等信息。记忆不是一份经过人工核对的知识笔记，也不能替代自己维护Obsidian。工作区可单独选择启用的知识库、技能等资源；切换后看不到某个库时也检查资源分配。

外部Agent、伙伴、协同写作、可视化和深度研究可按需求再开启。它们可能依赖额外模型、工具或连接。当前学习阶段优先把真实课件问答、独立练习、来源核对做扎实，不需要为了本月考核把每项功能都搭好。

## 11. 给喜欢终端或Agent的成员：可复现命令

先进入自己的项目和虚拟环境，并保证每次使用同一个运行home。Mac/Linux示例：

```bash
cd /你自己的/DeepTutor
export DEEPTUTOR_HOME="$PWD"
source .venv/bin/activate
```

Windows PowerShell示例（改为本人真实路径与已安装环境）：

```powershell
Set-Location 'E:\DeepTutor'
$env:DEEPTUTOR_HOME = (Get-Location).Path
```

如果激活脚本受策略限制，可以直接调用 `.venv\Scripts\deeptutor.exe`，不需要为了本教程放宽系统全局执行策略。以下命令以 `deeptutor` 已在当前PATH为前提；先运行`kb list`，将“课程库名”和“本次问题”替换为自己的实际库名及问题，不默认选择历史测试库：

```bash
deeptutor kb list
deeptutor kb info 课程库名
deeptutor kb search 课程库名 "本次问题" --format json
deeptutor run chat "本次问题，请标明资料来源。" --kb 课程库名 --language zh --format json
```

新建和追加会修改知识库；在选择好本人库名与资料后再执行。已有同名库不要重复create：

```bash
deeptutor kb create my-course-kb --doc "课件的实际绝对路径.pptx"
deeptutor kb add my-course-kb --doc "第二章课件的实际绝对路径.pptx"
```

当前CLI的 `kb create` 创建LlamaIndex库；不同引擎选择先走对应界面和当前帮助。`kb info` 本身输出JSON，不支持额外的 `--format json`；不要照搬其他子命令的参数。遇到版本差异先查看 `deeptutor kb --help` 和相应子命令帮助。

不要将 `DEEPTUTOR_HOME` 指到 `data/` 子目录或团队Git仓库来“同步资料”，这样会混淆运行设置、数据与共享文档。

## 12. 常见问题：按现象定位

| 现象 | 优先检查 | 保留什么证据 |
|---|---|---|
| 页面打不开 | 启动输出、实际端口、后台ready状态、启动日志；不要先重装 | 版本、运行目录、命令、报错末段 |
| 能开网页但不能回答 | 聊天模型配置、网络、Key权限与供应商余额 | 模型名与错误码，隐藏Key |
| 能普通聊天但建库失败 | Embedding、解析依赖、文件是否有效、失败阶段 | 失败文档、任务日志与模型维度 |
| 页面没有课程库 | 是否同一home、账号、工作区；该工作区是否分配了资源 | 当前范围、库名、列表状态 |
| 明明有文件却说没资料 | 文件是否索引就绪；对话是否挂载库；检索是否真正命中 | 问题原文、检索片段和引用 |
| 出现测试知识库内容 | 移除无关挂载，新对话只选真实课程库 | 当前选中标签 |
| 公式、图示解释错 | 纯文字提取局限、原PPT/图片是否实际读取 | 原页与提取结果差异 |
| 页码不一致 | PPT页、PDF物理页与印刷页是否混淆 | 原文件和实际位置 |
| 更换embedding后不能查 | 模型/维度与已有索引签名是否一致 | 原模型、新模型与需重建提示 |
| 视频/文章链接没读到 | 是否获取到正文或字幕；登录与网络限制 | 实际读取范围，不编造已看完 |
| 长对话答非所问 | 当前挂载、旧上下文、问题是否过大 | 开新对话保留简要目标与引用 |
| 想让队友看自己的库 | 先判断共享原文件还是共享服务；Git不会传递本机索引与账号 | 资料版本与队友复测记录 |

李卓凡本机便捷启动项的超时提示会指向项目 `data/user/runtime/launcher.log`。队友日志位置按自己的运行home查，不把他人绝对路径当通用路径。诊断前保留已有数据；不要一上来删除整个data目录或升级所有依赖。

## 13. 按这一张清单完成第一次学习

- [ ] 能打开自己的DeepTutor，知道怎么启动、怎么找到运行目录。
- [ ] 能说明聊天模型、embedding和文档解析分别负责什么。
- [ ] 成功导入一份真实课程文档，库状态可用，检索命中特有内容。
- [ ] 新对话只选目标课程库，能从输入框确认所选标签。
- [ ] 实际问了一个自己的问题，回看原课件核对至少一处引用。
- [ ] 完成与本次目标相符的独立练习、复述、复现或应用核对；未做时如实保留待办。
- [ ] 保存原问题、回答、本人反馈、纠错和来源，没有让AI代造心得。
- [ ] 将选择共享的学习记录提交团队PR，队友留下一条真实检查意见。

完成到哪一项就记录到哪一项。导入、提问、本人掌握、同伴复测分别报告，不用一个“已完成DeepTutor”笼统概括。
