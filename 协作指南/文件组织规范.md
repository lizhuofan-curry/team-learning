# 文件组织规范

新增资料先判断所属课程、实验或主题，再放入已有目录并检查引用。本规范适用于成员手动上传和 Agent 整理，避免把仓库变成零散文件堆。

## 1. 放在哪里

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| 根目录 | README、课程分工和资源索引等总入口 | 零散课件、截图、压缩包、学习笔记或代码 |
| 协作指南/ | Git、Agent、协作与文件规则，以及可复用模板 | 课件、个人学习笔记 |
| 课程资料/课程名/ | 真实课程资料、来源说明、DeepTutor导入和使用记录 | Agent Book的实验记录 |
| 实验记录/项目名/ | 按章节或实验编号组织的运行记录、关键代码、日志和分析 | 完整虚拟环境、模型和大型数据集 |
| 共同知识/主题名/ | 可复用概念笔记、源码分析、核对后的讨论结论 | 未整理聊天全文、重复粘贴的课件 |
| 周报/成员姓名/ | 按真实周次保存的本人确认原文 | 别人的经历或后做成果倒填 |
| 周报/附件/ | 按周或成员区分的周报图片等附件 | 无归属的图片 |

`.github/`、`.agents/`、`scripts/`、`tests/`是工具与维护代码目录，保留技术名称，不存学习资料。新的顶层分类先在PR说明用途并更新规则，不临时创建“其他”“杂项”“临时资料”等长期堆放区。

## 2. 按需建立，避免空目录

课程、项目、知识主题目录有实际资料时才建立，并提供一份 `README.md`，作为该目录的入口。每份入口说明应能回答：谁负责、覆盖什么、资料来源、主要文件链接、完成到哪里和待核对什么。缺少实际信息写“待确认”，不编造负责人或学习成果。

以下是结构示意，不表示这些课件、代码和使用记录已经存在，也不要求一次创建全部子目录：

```text
课程资料/
└── 数据结构/
    ├── README.md
    ├── 课件/
    │   └── 数据结构_课件_第02章线性表_2026秋.pdf
    └── 使用记录/
        └── 数据结构_DeepTutor使用记录_线性表_2026-10-27.md

实验记录/
└── AgentBook/
    ├── README.md
    └── 第01章/
        ├── README.md
        └── 1-1/
            ├── README.md
            ├── lizhuofan-curry/
            │   ├── 1-1_lizhuofan-curry_实验记录.md
            │   └── 运行结果/
            └── hhbb56/
                ├── 1-1_hhbb56_实验记录.md
                └── 附件/

共同知识/
└── Agent基础/
    ├── README.md
    ├── ReAct原理与适用范围.md
    └── 附件/
        └── ReAct原理与适用范围/
            └── 工具调用流程.png
```

课程子目录可使用“课件、笔记、练习、使用记录、附件”，只建立本次真正需要的目录。项目继续保留源码原有的包结构和文件名，不强行给函数、模块或配置文件加中文前缀。

## 3. 怎么命名

- 资料名尽量表达“课程或主题_类型_章节或主题”，版本、学期、日期只有确实影响适用性时才添加。不要把年份猜出来。
- 日期统一 `YYYY-MM-DD`；周报沿用 `姓名YYYY-MM-DD_YYYY-MM-DD_周报.md`。
- 不使用“未命名”“新建文件”“新建文本文档”、结尾“副本”或 `final_final` 等模糊名称。用明确主题或版本差异替代。
- 不使用 Windows 不兼容的 `< > : " \\ | ? *`，不创建仅大小写或Unicode规范形式不同的重名路径，方便成员在Windows、Mac和CI间协作。
- 文件和目录不使用 Windows 保留名称，例如 `CON`、`AUX`、`NUL`、`COM1`、`LPT1`；带扩展名也不行，例如 `CON.pdf`。`CONCEPT.md` 等普通名称不受此限制。
- 外部课件需要规范名称时，整理上传副本，在课程README记录原文件名及来源；不擅自修改用户原始文件或代码包结构。

## 3.1 同一个实验的多人记录

编号实验统一使用`实验记录/项目名/第NN章/章号-实验号/成员GitHub账号/`，主记录文件为`章号-实验号_账号_实验记录.md`。例如`实验记录/AgentBook/第01章/1-1/lizhuofan-curry/1-1_lizhuofan-curry_实验记录.md`。这里1-1来自教材实验编号，不是成员自创的新编号；不把缺失实验补成完成。

从PR阶段开始强制检查：现有“检查文档链接和附件”CI会运行命名检查，PR创建、重新打开和新增提交时都触发。失败时按具体路径修正后重新推送，不要求在成员私人项目中提前改名；上传团队归档副本时规范化。main已要求通过这项CI时，失败的PR无法正常合并。CI校验路径和文件名，不校验账号是否确属作者或实验是否真实完成，后两项由同伴审阅。

- 章节写两位数字，如第01章；实验用教材常用的1-1、1-2、2-10，不把1.1和1-1并列成两个实验。
- 成员目录使用自己的小写GitHub账号，避免姓名重名及改名影响。正文可同时写姓名与账号，未知成员姓名不猜测。
- 实验根目录的README汇总各成员真实记录及差异；`对比分析.md`用于实际共同核对后的比较。其他个人材料放本人目录，不共用一个`实验记录.md`互相覆盖。
- 代码、截图、原始输出和补充分析都留在本人目录内部，可保留原包结构和原文件名；不要求给每个Python模块或JSON前缀加姓名。
- 同一成员持续更新同一记录，Git保留修改历史；多次运行按原真实运行编号或`YYYY-MM-DD_HHMMSS`分目录，避免`最终版2`和重复副本。
- 不同成员做同一题是独立记录，不能按文件名或相似内容自动合并、去重或覆盖。参考他人成果时注明来源和自己的实际验证范围。

只有本次有真实内容时才建立成员或实验目录；上方两个账号只是结构示例，不据此创建空目录或声称队友已完成。可从[实验记录模板](模板/实验记录模板.md)开始，已有记录保留正文、日期和失败，不为了套模板重写。

## 4. 附件、重复文件和更新

附件放在所属课程、实验或主题目录内部的“附件”中，必要时再按文档主题分组。正文使用相对链接，不引用个人电脑绝对路径。周报已有附件布局继续沿用。

新增内容前先搜索已有文件和资源索引。同一资料尽量只保存一份，其他文档链接过去；不同年份、讲授版本或勘误版应明确差异，不能只因名字相似就删除。覆盖前比较内容，移动后更新引用；不自动清理或删除他人资料。

一次PR尽量围绕一门课、一个实验或一个明确主题。PR列清新增、移动、替换的文件和原因，不将无关整理混入。

## 5. 入口和索引怎样配合

根目录[资源索引](../资源索引.md)登记课程或项目的入口链接、用途和来源状态；每门课或主题的README列具体文件。只添加一张已引用的图片，不需要在总索引再登记一行。

新增课件或笔记时更新所属README；新增课程或项目入口时更新总索引；课程负责人和覆盖进度统一更新[分工与课程覆盖](../分工与课程覆盖.md)，不在多处维护不同分工表。

## 6. 自动检查与人工核对

本地运行：

```bash
python3 scripts/check_layout.py .
python3 scripts/check_docs.py .
```

布局检查会报告：根目录或学习区第一层散落资料、未知顶层目录、课程/项目/主题缺少README、明显临时名称、不兼容名称和仅大小写等不同的路径冲突；编号实验还检查章节编号、成员目录和主记录文件名。链接检查继续核对仓库内正文引用和附件。新文件也会检查，Git忽略的本机文件不纳入。

程序不能判断课件是否放错学科、来源是否准确、附件是否真正有用，或内容是否正确；这些仍由提交者与同伴核对。README文件存在，也不等于说明内容已写完整。检查通过不表示已经启用分支保护或平台强制审阅。

规则需要例外时，在PR中说明原因并调整适用规则，不通过改后缀、塞进技术目录等方式绕过。历史材料只在本次任务需要时逐项整理，不全库批量搬动。
