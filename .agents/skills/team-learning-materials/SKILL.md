# 团队资料整理与 PR 协作

将用户指定、同意共享的普通资料整理成同伴能够核对和使用的贡献。技能可自动匹配整理任务；创建远程分支或 PR 的授权仍来自用户当前请求及既有会话，不由本技能扩大。

## 读取团队约定

先读仓库根目录的 [README](../../../README.md)、[协作约定](../../../协作约定.md)、目标目录说明，以及 [PR模板](../../../.github/pull_request_template.md)。涉及课程认领时读 [分工与课程覆盖](../../../分工与课程覆盖.md)，新增共享资源时维护 [资源索引](../../../资源索引.md)。这些文档是规则和状态入口，不另造一套进度表。

检查本机工作区、当前分支和远端变化；同步失败就不能声称已取得最新状态。保留队友和用户的未提交内容。任务需要修改文件时，从已核对的主线建立独立分支；遇到分叉或冲突先核对相关内容，不强推或丢弃修改。

## 整理范围

| 目录 | 保存内容 | 需要保留的依据 |
|---|---|---|
| 实验资料 | Agent Book 实验记录、关键代码与日志，或完整项目的仓库链接 | 项目版本、命令、模型与环境、实际输出、失败、分析 |
| 课程资料 | 可共享的真实课程资料、DeepTutor 导入与实际使用记录 | 来源、章节、课程负责人、导入状态、实际提问与引用核对 |
| 共同知识 | 共享笔记、DeepTutor 源码分析、已核对的讨论结论 | 作者、日期、来源、代码版本或文件函数、核对状态 |
| 周报 | 成员本人授权归档的已确认周报原文及附件 | 真实周次、原文、图片链接；不改写经历或代替邮件提交 |

按本次范围整理，不批量搬入个人库，也不顺便重构其他目录。使用相对链接，附件随正文保存；大项目、模型、数据集和运行环境使用来源链接，不整体复制进知识库。

个人总结或读后感可以由大模型辅助提供思路、提出问题和组织表达，再由本人结合实际阅读与经历修改、确认。资料归档与内容构思按用户指定范围处理，不自行编造阅读过程或个人体会。

## 来源与核对

- 来源和作者有依据才填写；作者与收集者分开，未知信息标注待确认。不得把 AI 生成内容伪装成原始课件或真实实验输出，不得编造本人经历或把辅助建议写成已验证事实。
- 分别标记本人真实运行、离线复核、教材参考、AI 辅助解释和计划。资料存在、成功入库、回答可靠、同伴复测是不同状态。
- 用户没有提供的运行、课程使用、讨论、审阅或团队贡献，不得补写为已发生。发现矛盾时保留原始证据并说明疑点。
- 只上传同意共享的内容。排除密钥、.env、私人聊天、账号状态等；保持仓库既有私有设置，资料公开需另有明确授权。不要在输出中复述发现的完整凭据。

## 检查与交付

核对本次文件的相对链接、图片附件、目标目录和明显重复内容；按实际内容检查依据。存在适用检查脚本时，先查看用途再执行；不存在时报告人工或临时检查的范围，不编造 CI 或脚本通过。

文件移动、重命名时更新引用；原始周报若只需更正附件链接，仅改链接并在 PR 说明。现阶段维护资源索引即可，不为使用本技能强行引入 manifest。

完成后检查差异，只暂存本次文件，避免全量暂存混入队友工作。按用户已授权范围完成本地整理；需要提交 PR 时：

1. 检查提交者身份，使用成员本人已配置账号，不伪造其他成员署名。
2. 提交并推送任务分支，按模板创建草稿 PR，写清来源、检查方式、未确认项和同伴重点核对点。
3. 不自动合并，不以 Agent 自查代替同伴审阅。工具能力或权限不足时保留已完成成果，说明具体阻碍。

返回文件位置、实际检查结果，以及成功创建的 PR 链接。没有执行的操作明确写为未执行。
