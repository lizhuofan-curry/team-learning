# 学习验收与优先级

用于对照课程、实验室或本人学习计划检查当前进度，并给出可执行的补齐方案。只核对本次要求涉及的材料；已掌握的通用操作不需要再展开成新教程。

## 先确认要求和证据位置

1. 从用户指定的要求中列出交付物、学习目标、提交方式、截止时间及适用范围。聊天中的相对日期按该消息日期与时区推算，并标为推算目标；没有确切截止日或存在新通知时保留待确认，不把自己的建议日期写成老师要求。
2. “全部实验”“每人至少一门”“全部心得”等需要完整清单和版本口径。区分课程原要求、本人选定的轻量学习范围、暂缓/跳过项及明确批准的豁免；本人选择跳过不能自动算满足原必做要求。目录数或上游实验台账不等于本人的完成数。
3. 从本次提供或已授权的成员配置确定`personal_vault`、`team_repo`、`deeptutor_root`与工作流目录；个人库和团队库分别读自己的AGENTS.md。没有配置时先用用户已给出的真实位置，不照抄其他成员路径、账号或服务器设置。
4. 在`team_repo`内按任务读取已有分工表、资源索引及相关手册：协作看“协作指南/团队知识库完整使用手册.md”，课程使用看“协作指南/DeepTutor完整使用手册.md”。以文件实际存在和当前版本为准；全局安装的Skill仍用成员配置定位这些文件，不拼接越出Skill的相对路径。
5. 找到足以支持当前判断的原始输出、本人反馈或提交记录就停止扩读。记录本次读取范围、检查日期和缺口；不为进度核对扫描全部私人聊天、无关raw或其他成员个人材料，不为凑证据重新运行付费模型或改变实验协议。需要特定材料时按当前任务授权处理。

## 分开验收这些层次

| 层次 | 有效证据例子 | 不足以单独证明的东西 |
|---|---|---|
| 实验真实运行 | 运行条件、版本、命令、实际输出、失败与分析 | 脚本已生成、环境已装、上游参考结果 |
| 本人理解和代码能力 | 本人能解释输入输出，完成小修改并验证 | AI讲解或生成代码，检查器全绿 |
| 课程真实入库 | 原材料版本、解析/索引状态、实际检索命中 | 文件已下载或已经进入Git |
| 本人课程学习 | 原问题、回答、引用核对及本人反馈 | Agent代执行问答、材料目录齐全 |
| 独立验证 | 与任务相符的本人分析、解题、复现或应用过程及错误修正 | 看过答案、说“听懂了”、系统进度条 |
| 源码实践 | 固定版本、真实调用链、本人说明、小改动与验证 | AI准备的阅读路线或架构图 |
| 团队接入 | 成员自己接受邀请、可访问并完成本地克隆 | 仓库已创建或邀请已发出 |
| 团队贡献与互审 | 各自具名提交、关键结论核对和实质意见 | 一个人代传全部资料、AI自查、PR合并按钮 |
| 共同使用 | 队友拉取后实际打开/复测，留下结果 | 远端main有文件或CI通过 |
| 个人吸收与自生长 | 引用团队文件/版本，记录本人问题、验证、修正及新情境复用 | 全量复制团队库、概念数量或图谱变密 |
| 周报与作业提交 | 本人确认的实际提交情况，或可核对回执 | 本地文件、草稿、仓库归档 |
| 自动工作流 | 实际运行覆盖范围、输出、失败和本人版本确认 | 定时开关、服务PID、一次隔离测试 |

微信原话、AI摘要、本人学习收益和系统测试分别记录。语音合成样本不能替代真人微信语音验收；链接存在不能证明文章正文、视频字幕或画面已读取。工作流能力的具体判定沿用其现有Skill及实测记录，不因一次测试推广为所有平台可用。

## 处理过时入口与证据冲突

总README、分工表、实验子目录与历史周报可能更新不同步。先查看对应版本、日期、最新结果和来源，再区分“入口过时”“后续完成”“仍待本人确认”。旧记录中的待做不自动否定后续实测，最新一句“已完成”也不能覆盖未解决的失败或范围限制。

需要修正文档时，指出具体冲突及依据，只在本次授权范围更新入口状态；保留原始输出和当时的周报，不把后来成果倒填历史。没有充分证据则报告矛盾及确认动作，不为了让表格一致自动重跑或删掉失败。

## 交付一份可以执行的计划

对每项要求列出：状态、判断依据与位置、还缺什么。状态使用“已核实完成、部分完成、待本人确认、未找到证据”；本人确认和工具直接核实分别标注。没有完整分母、权重和统一验收口径时，不报一个总完成百分比。

再按实际截止时间、考核重点和依赖排序，通常可用：

- **P0**：近期必须提交的材料、影响本人能力或真实团队合作的核心缺口，以及阻断下一步的依赖。
- **P1**：近期可完成的独立练习、源码实践、课程共享复测、知识吸收和证据整理。
- **P2**：在真实使用后再改进的自动化、媒体入口或额外平台；若它实际阻断P0，则按依赖提前，不机械固定等级。

每个动作说明谁来做、使用哪份实际材料、具体步骤、验收证据与建议时间或前置条件；建议与正式截止时间分开。不把“多学习、加强交流、继续完善”当作具体方案，也不靠增加目录、Skill或平台替代真实学习。无须为完成计划而让一人代写三人的经历或贡献。

只将本人选定的可共享材料通过团队分支和PR贡献。私人进度分析、收件箱、未审核周报、本机配置及完整个人库不自动进入团队；已批准的归档、Git合并、老师收到和同伴实际使用仍分别验收。涉及报告构思、阅读或写作时按本次用户指定的材料与协助范围处理，不把一般仓库约定当作特定任务已经获准或已经提交的证据。
