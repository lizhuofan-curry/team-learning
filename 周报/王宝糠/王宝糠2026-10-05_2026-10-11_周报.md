# 周报（2026年10月5日 — 10月11日）

## 💡 本周思考

**关于「Vibe Coding」把想法变成工具**：本周用 Vibe Coding 做成了一个 Markdown 转 PDF 的网页，解决的是我自己反复遇到的真问题——md 文件里的图片转 PDF 后经常显示不出来。上周我做的是给 DSH 写插件，这周是独立做一个完整的网页工具，两次的体会是一致的：AI 已经把「发现问题 → 做个小工具解决掉」的闭环成本压得很低，真正稀缺的不是写代码的能力，而是能不能准确发现问题、把需求讲清楚。接下来我想把这种能力用在更多真实的重复劳动上。

**关于 Agent 的认识升级**：本周把《AI-Agent-in-Depth》第二章「上下文工程」学完了。上周是「初步认识」，这周最大的变化是**能用起来**——我知道了上下文里该放什么、按什么顺序放、什么该丢给检索，于是使用 Agent 完成工作时不再是碰运气式地提问，而是有意识地设计上下文。这个转变很直接地体现在效率上：同样是让 Agent 干活，能不能用科学的方法给它上下文，产出质量差得很远。

**关于论文的「读懂」标准**：本周精读了 MindEye2、CLIP、ResNet 等经典论文并整理了详细笔记，同时成功复现了 Z-Star 零样本风格迁移。配合这周学会的 Visio 绘图（周五独立画出了一张神经网络架构图），我逐渐形成一个判断：**论文读懂的标志不是"看懂文字"，而是能画出它的架构图、并把它复现出来**。图和代码会立刻暴露理解里含糊的地方。下周打算继续把这条路径固定下来：精读 → 画架构图 → 复现。

**另一条贯穿全周的隐性线索是「想把事情做完美再交出去」**：本周个人知识库没建起来（Obsidian 还不熟）、英语长文章阅读没做、自己的项目也没上传 GitHub——第三个尤其典型，理由不是没做完，而是「觉得还有很多可优化的地方」。这三件事的共同点是把「不理想」当成了「不能开始」的理由。上周我已经意识到要把任务拆成最小可执行单元，这周的问题出在另一头：先完成、再完美。下周项目先上传 v1，知识库先搭最小目录，长文章先拆成固定时段。
