# 三人团队学习知识库

这里保存三人的课程资料、实验记录、共享笔记和已确认周报。我们通过 **Git 分支 → Pull Request（PR，合并请求）→ 同伴审阅 → 合并 → 拉取复用** 完成协作。

**把链接交给 Agent**：只发网址不保证所有 Agent 都会读取协作规则。建议连同下面这段一起发；已有本地副本的成员直接让 Agent 打开该目录，不需要全局安装 Skill。

```text
这是我们的团队仓库：https://github.com/lizhuofan-curry/team-learning
请先读 README.md、根目录 AGENTS.md，以及“协作指南/Agent资料整理指南.md”的“从仓库链接开始”。
带我完成第一次协作，优先整理我提供的一份真实材料，不要只总结仓库或让我先读完整手册。
先检查你能否读网页、访问本地文件及执行命令；复用已有克隆，缺少路径时再问我选在哪里。
我允许你在我选定的位置克隆、整理本次材料并运行检查，保留已有修改。
身份、材料或用途不清楚时，只问当前下一步缺少的信息，不猜课程分工或替我编造经历。
完成后展示文件差异和验证结果；远程提交、请求审阅与合并按我之后的明确授权执行。
工具不能执行的步骤，给出我当前能照做的一步和预期结果，再继续跟进。
```

网页工具不能自动发现文件时，先打开[完整地址的AGENTS入口](https://github.com/lizhuofan-curry/team-learning/blob/main/AGENTS.md)，再按[从仓库链接开始](协作指南/Agent资料整理指南.md#从仓库链接开始)逐步带做。Agent应说明“当前阶段、已检查结果、你现在只需做的一步”，不把技能存在当作账号和服务已配置。

**希望自己操作**：从下方[新成员开始协作](#新成员开始协作)往下做。第一次贡献可以只提交一份真实材料，不必先搭好 Hermes、Obsidian 和 DeepTutor。

## 让 Agent 带我完整接入个人学习系统

希望接好个人知识库、Hermes 和学习工作流时，把下面整段连同仓库链接交给自己的 Agent。上方提示词用于第一次资料贡献；本段会明确选择[完整接入路线](协作指南/Agent资料整理指南.md#完整接入个人学习系统)，由 Agent 先检查已有组件，再逐步配置和验证。

```text
我们的团队仓库：https://github.com/lizhuofan-curry/team-learning
请先读 README.md、根目录 AGENTS.md，以及“协作指南/Agent资料整理指南.md”的“完整接入个人学习系统”。
这次目标是完整接入我的个人学习系统，不只是提交一份团队资料。
使用仓库内 lab-knowledge-loop 和 lab-weekly-flow 的新成员接入说明，先检查我已有的：
1. Hermes 安装、实际运行位置、模型对话和微信连接；
2. 本地个人知识库、GitHub 个人私有仓库及 Git 同步；
3. Obsidian 安装情况及是否打开正确的个人库；
4. 团队仓库克隆、本人账号、邀请接受情况和提交身份；
5. 学习采集、日记、周报及已有定时任务的配置和实际运行记录。
把手动记录、自然对话自动保存、素材同步、双向协作、定时整理和可选媒体补读分别说明，按我已有选择配置；尚未选择的项目再问我，不默认全部开启。
先说明你能否访问网页、本地文件和执行命令；已有组件直接复用，保留笔记、配置和未提交修改。
我允许你在我选定的位置完成本次所需的本地安装、建库和配置；缺少路径时再问我。
需要新建个人远端时，在我的账号创建私有仓库并连接；推送前展示拟上传范围，按我的明确授权上传。
登录、密钥填写和微信扫码由我在自己的安全界面完成，不向聊天索要凭据。
缺失组件逐步带我配置，每一步报告实际检查结果，配置后做真实验证。
不要把创建目录、找到命令或生成配置当作全部部署成功；工具不能执行时给我当前可操作的一步和预期结果。
定时任务先说明执行位置、频率及离线限制，由我选择后再设置，不重复创建已有任务。
个人库与团队库分开，不上传私人素材到团队库，不代我批准周报、发送邮件或合并团队 PR。
最后逐项交付已验证、待验证和阻碍，以及下一步需要我做什么；保留进度，下次从未完成处继续。
按接入状态说明把选择、证据和下一步保存在我私人工作流的“接入状态”目录；不要用初始化探测报告冒充全部验收。
```

具体操作分见[个人库、GitHub 与 Obsidian 接入](.agents/skills/lab-knowledge-loop/references/onboarding.md)和[Hermes 与学习工作流首次接入](.agents/skills/lab-weekly-flow/references/first-run.md)。Obsidian 打开的是个人 Git 仓库对应的本地文件夹；团队仓库另放独立目录。配套接入脚本只做部分检查和本地初始化，安装、账号连接、同步、微信收发与定时运行分别验收。

个人库指南包含首次私有上传、已有远端的处理及可选 Obsidian Git 操作；首次接入指南区分仓库克隆/技能包解压的命令路径，并列出自动化模块的选择与验收。中断后按[私人接入进度](.agents/skills/lab-weekly-flow/references/onboarding-state.md)继续。

## 新成员开始协作

### 1. 使用自己的账号，取得本地副本

需要直接向团队仓库推送分支的成员，先用自己的 GitHub 账号接受协作者邀请；只浏览公开资料不需要写入权限。各自克隆同一个团队仓库，不另建三个平行团队仓库，也不把它克隆到另一个 Git 仓库内部。

```sh
git clone https://github.com/lizhuofan-curry/team-learning.git
cd team-learning
```

已经克隆的成员使用现有副本；先检查工作区，保留自己未提交的内容，再更新。也可以用 GitHub Desktop 克隆和提交，步骤见[Git 协作入门](协作指南/Git协作入门.md)。

### 2. 认领一件事，在自己的分支上做

先查看分工表，与队友确认本次负责的实际课程、实验或主题，再从更新后的主线新建任务分支。不要三个人同时覆盖同一份个人记录。

以下命令在工作区干净时执行；先把 `yourname` 换成自己的 GitHub 账号，分支后半段换成实际任务。同一任务已有分支或开放 PR 时，继续使用它。

```sh
git switch main
git pull --ff-only
git switch -c yourname/add-one-record
```

### 3. 放入一份真实材料，补齐入口

按上方目录表选择位置，遵守[文件组织规范](协作指南/文件组织规范.md)。第一份贡献可以是一项实验记录、一份课程资料及来源说明，或一篇有依据的共享笔记。

- 保留实验或笔记正文及必要附件，写明作者、来源、实际完成范围、问题和下一步。
- 区分本人真实运行、离线复核、教材参考、AI 辅助与计划；失败记录也有价值。
- 不同成员的实验结果分别保存，不因编号相同就覆盖或合并成一人的结果。
- 更新所属目录 README，让别人能找到新文件；新建课程或项目入口时再补资源索引。
- 只为已有材料建目录，不创建一批空文件夹，不使用“未命名”“副本”“final_final”等模糊名称。

可按需使用[课程入口模板](协作指南/模板/课程入口模板.md)、[共享笔记模板](协作指南/模板/共享笔记模板.md)和[DeepTutor 使用记录模板](协作指南/模板/DeepTutor使用记录模板.md)。模板中的待填项需要真实填写。

### 4. 检查、提交，再发起 PR

从仓库根目录运行；Windows 可将 `python3` 换成本机可用的 `python` 或 `py -3`：

```sh
python3 scripts/check_layout.py .
python3 scripts/check_docs.py .
```

检查后查看 `git status` 和实际差异，只提交本次改动。Commit 保存本机版本，Push 上传任务分支；随后在 GitHub 的 Pull requests 中创建 PR，目标分支选择 `main`。

按[PR 模板](.github/pull_request_template.md)说明：改了什么、资料来源、实际读过或运行过什么、检查结果、尚未完成什么，以及希望队友重点核对的一处具体内容。未执行的检查写“未运行”，不勾成通过。

完整提交命令与桌面操作见[Git 协作入门](协作指南/Git协作入门.md)。第一次贡献的目标是让另一成员能找到、核对和实际使用这份材料。

## 队友如何审阅与合并

1. 在 PR 的 **Files changed** 查看本次改动，打开相关正文、附件或来源；根据内容抽查公式、引用、运行条件或结果，不只看文件名。
2. 留下具体意见，说明文件位置、问题及依据；完成核对后按实际情况选择 Comment（评论）、Request changes（要求修改）或 Approve（批准）。评论不等于批准。
3. 作者在同一任务分支修订并推送，PR 会更新；审阅者复核新提交与相关检查。不要把旧提交的通过状态当作新版已经核对。
4. 满足当前分支保护、检查与同伴审阅要求后，由有权限的成员合并。CI 检查结构、链接和附件，AI 可辅助找问题，二者都不代替另一成员的实际审阅。

合并后，在各自工作区干净时执行下面命令，取得共同版本并实际阅读或复用：

```sh
git switch main
git pull --ff-only
```

一次协作完成的证据包括：自己的材料、对应 PR、队友的具体反馈、合并后的获取或使用；不按文件数或提交次数机械比较贡献。发生冲突或认证失败时保留现场，先核对原因，不强推或删除 `.git`。

## 给 Agent 的入口

在 Agent 中打开本仓库根目录。支持 AGENTS.md 自动加载的工具可从规则入口开始；其他工具明确要求先读取 [AGENTS.md](AGENTS.md)。入口会指向[分阶段执行流程](协作指南/Agent资料整理指南.md#agent-执行流程)，由 Agent 检查、整理、验证，并按已有授权提交或交接结果。

本仓库有三套 Skill，Agent 按本次任务选择，不必全部执行：

| Skill | 什么时候使用 | 预期结果 |
|---|---|---|
| [team-learning-materials](.agents/skills/team-learning-materials/SKILL.md) | 整理、命名、上传资料，准备 PR，审阅指定 PR 或按意见修订 | 放置正确、来源清楚的文件、必要索引、检查结果及 PR/审阅草稿 |
| [lab-knowledge-loop](.agents/skills/lab-knowledge-loop/SKILL.md) | 建立个人知识库、核对学习进度、吸收团队知识或整理真实学习证据 | 可追溯的个人笔记、来源关联、实际结果与待办 |
| [lab-weekly-flow](.agents/skills/lab-weekly-flow/SKILL.md) | 接入 Hermes/微信采集，整理学习记录及周报，按本人确认版本归档 | 本人的学习素材、待审核周报、明确版本和归档状态 |

可以复制下面的任务说明，把方括号内容换成真实信息：

```text
先读本仓库的 AGENTS.md 和 README.md，按任务选择对应 Skill。
我的任务：[例如整理并提交本人的一份实验记录，或审阅指定 PR]。
输入材料或 PR：[实际路径或链接]。
核对已有目录、任务分支和 PR，保留我和队友的修改。
写清来源、作者、实际结果与待办，更新所属 README 和必要索引，运行相关检查。
按我本次及已有授权完成操作；要求提交 PR 时，继续同一任务已有 PR，不自动合并。
返回实际改动、检查结果和下一步；未读取或未执行的部分明确说明。
```

只审阅时，Agent 先交付意见，不修改作者分支或自动发布批准；只有本人明确授权发布评论时再发布。需要搭个人库或 Hermes 时，先检测已有环境，按[新成员首次接入](.agents/skills/lab-weekly-flow/references/first-run.md)引导，不重复安装或向聊天索要密钥。

## 个人知识库、DeepTutor 与周报怎样配合

- **团队仓库**保存选定的共享材料及协作历史；**个人 Obsidian 库**保存自己的理解、试错与学习路径，各成员独立维护。
- **DeepTutor**读取实际导入并挂载的资料，用于问答、练习及引用核对；Git 拉取文件不会自动更新它的知识索引。
- **Hermes 与 Codex**可按各成员自己的配置采集学习素材、整理知识和更新周报。克隆仓库或读取 Skill，不代表账号、微信、同步程序和定时任务已经部署。
- 本人确认的周报才进入团队归档；个人收件箱、私人聊天、未确认草稿、密钥、账号状态、完整运行环境和大型模型不上传。
